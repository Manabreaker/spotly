# Spotly

Одностраничная форма создания мероприятия с восстановлением черновика по индивидуальной ссылке и сохранением истории заполнения. Python 3.14, FastAPI, PostgreSQL 18. Данные не публикуются.

## Создание мероприятия

Откройте `https://spotly.awkward-scarlet.ru/create/<uuid>`. Подойдёт любой самостоятельно выбранный UUID; предварительно выпускать или регистрировать ссылку не нужно. Одна ссылка создаёт одно мероприятие. Знание ссылки позволяет читать её черновик и продолжать заполнение, поэтому не публикуйте её до завершения проверки.

Случайный UUID можно получить командой `python3 -c 'import uuid; print(uuid.uuid4())'`. Сопоставление ссылок организаторам храните отдельно. На форме имена и контакты не запрашиваются.

## Локальная разработка

Установите uv из официального реестра и выполните `uv sync --locked`. Нужен PostgreSQL 18. Пример отдельной тестовой базы:

```sh
docker run -d --name spotly-test-pg -e POSTGRES_PASSWORD=spotly-test-only -e POSTGRES_DB=spotly_regression_test -p 127.0.0.1:55432:5432 postgres:18
export DATABASE_URL=postgresql+psycopg://postgres:spotly-test-only@127.0.0.1:55432/spotly_regression_test
uv run alembic upgrade head
uv run uvicorn spotly.main:build_app --factory --port 8765 --no-access-log
```

Для ручной браузерной проверки используйте другую базу. API-тесты пересоздают таблицы только в явно указанной базе с суффиксом `_test`; не указывайте базу с сохраняемыми записями.

```sh
TEST_DATABASE_URL=postgresql+psycopg://postgres:spotly-test-only@127.0.0.1:55432/spotly_regression_test uv run pytest -q
uv run ruff check spotly tests migrations
uv run ruff format --check spotly tests migrations
node --check spotly/static/form.js
node --check spotly/static/telemetry.js
node --test tests/test_telemetry.mjs
```

Без TEST_DATABASE_URL проверки PostgreSQL пропускаются; верификацией API такой запуск не является.

## Запуск на сервере

В проекте нет реальных паролей. Создайте закрытый `.env` по образцу `.env.example` со случайным длинным POSTGRES_PASSWORD и APP_REVISION, равным хешу коммита. Приложение использует пользователя `postgres` по согласованию с владельцем; порт БД наружу не публикуется.

Каталог установки — `/opt/spotly`. Перед первым запуском создайте `data/photos` с владельцем UID/GID 10001, чтобы непривилегированное приложение могло сохранять изображения. Установите Docker с Compose и buildx. Выполните `sudo bash scripts/deploy.sh`. Миграции применяются перед стартом Uvicorn. Caddy получает и продлевает HTTPS-сертификат для указанного в Caddyfile домена; DNS должен вести на сервер, порты 80/443 должны быть доступны.

`data/`, `.env`, `.idea/` и рабочие файлы исключены из Git. Не используйте `docker compose down -v`, очистку каталога данных или удаление записей для обновления приложения. Изменения формата требуют новой миграции Alembic; существующие применённые миграции не переписываются.

Сервер имеет 1 CPU и около 2 ГБ RAM; добавлены 4 ГБ swap. Декодирование выполняется отдельным процессом, по одному фото одновременно. Увеличение ресурсов может улучшить скорость; лимиты 30 МБ/100 Мп от этого не уменьшаются.

## Сохранение и исследовательские данные

Черновик принимает незавершённые и невалидные ответы. Сохраняется через секунду паузы или каждые пять секунд непрерывного ввода, а также при завершении поля. Версия защищает от записи устаревшей вкладки; неотправленные правки остаются локально. Между устройствами доступны только подтверждённые сервером данные.

`attempts` содержит текущие и перезапущенные попытки, `events` — созданные мероприятия, `activities` — историю действий и снимки значений, `feedback` — отзывы, `photos` — сведения об изображениях. Для исследования используется производный внутренний participant_id, а не копия кода доступа в каждом событии. Идентификатор попытки связывает записи. Текст ответов и полные внешние ссылки сохраняются по согласованному ТЗ; предупредите участников до выдачи ссылки.

Оригиналы и WebP-превью хранятся в `data/photos`. Перезапуск формы или удаление фотографии из видимого списка не удаляет прежнюю историю и файл. Созданные браузерной проверкой записи также остаются.

## Резервные копии

`sudo bash scripts/backup.sh` создаёт согласованный набор PostgreSQL + фотографии в `data/backups/<UTC timestamp>`, манифест SHA256 и закрытую запись результата. Файлы изображений неизменяемы, а БД копируется до архива фотографий. Автоматического удаления данных и копий нет.

Установите `scripts/spotly-backup.service` и `scripts/spotly-backup.timer` в `/etc/systemd/system/`, затем включите таймер. Он запускается ежедневно в 06:00 по Москве (03:00 UTC). Перед обновлениями deploy.sh также выполняет копирование. Владелец сохраняет внешнюю копию набора по SSH/SFTP; копии на том же сервере не защищают от потери сервера.

Проверка восстановления выполняется в новой отдельной базе, не поверх рабочей:

```sh
sudo docker compose exec -T db createdb -U postgres spotly_restore_check
sudo docker compose exec -T db pg_restore -U postgres -d spotly_restore_check --no-owner < data/backups/НУЖНЫЙ_НАБОР/postgres.dump
```

Проверьте количество мероприятий, попыток, событий и наличие фотографий по манифесту. Рабочая база называется `spotly`; тестовые команды её не очищают.
